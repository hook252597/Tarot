# B 작업 요구 문서 — UI/UX · 카드 디자인

| 항목 | 내용 |
|---|---|
| 담당 | B (동업자) |
| 기준 문서 | `docs/DEVELOPMENT.md` v0.13 |
| 담당 폴더 | `css/`, `js/ui/`, `assets/` |
| 건드리기 전 A에게 알릴 파일 | `index.html`, `js/app.js` |
| 문서 상태 | 참고 이미지 접수(`assets/ui/s1~s4`). 7장·10장 화면 제안: `docs/UI_DESIGN_SPREADS.md`, 시안 `docs/mockups/spread-layouts.html` |

## 1. 이 사이트가 하는 일

1. 사용자가 메뉴(스프레드)를 고른다
2. 상황·고민을 글로 적는다(비워도 됨)
3. 펼쳐진 카드에서 정해진 장수만큼 고른다
4. 뽑은 카드를 보고, **AI에 붙여 넣을 프롬프트를 복사**한다

사이트 안에는 해석 글이 없습니다. 해석은 사용자가 복사한 프롬프트를 자신이 쓰는 AI에 붙여 넣어 받습니다. 그래서 **카드를 뽑는 경험**과 **"복사해서 AI에 붙여 넣으세요"가 바로 이해되는 결과 화면**이 디자인의 핵심입니다.

**지켜야 할 원칙**
- 쿠키·세션·브라우저 저장소를 쓰지 않음(테마 설정 저장 포함). 새로고침하면 처음부터 시작
- 외부 서버로 나가는 요청은 되도록 만들지 않음 — 아이콘·통계 도구는 쓰지 않거나 파일로 저장소에 넣기. 글꼴을 외부에서 불러올지는 B가 결정(4.2 참고)
- 횟수 제한 없음 — 언제든 다시 뽑을 수 있음

## 2. 메뉴 5종과 카드 배치

| 메뉴 | 장수 | 자리 | 결과 화면 배치 |
|---|---|---|---|
| **오늘의 운세** (대표 메뉴) | 3 | 상황 · 과제 · 결과 | 한 줄 3장 |
| 원 카드 | 1 | 핵심 메시지 | 1장 |
| 쓰리 카드 | 3 | 과거 · 현재 · 미래 | 한 줄 3장 |
| 관계 스프레드 | 7 | ① 나 ② 상대 ③ 두 사람의 관계 ④ 내가 원하는 것 ⑤ 상대가 원하는 것 ⑥ 관계의 과제 ⑦ 관계의 가능성과 흐름 | 4줄(1·2·3·1) — 아래 2.2 |
| 켈틱 크로스 | 10 | ① 현재 상황 ② 장애물 ③ 가까운 과거 ④ 가까운 미래 ⑤ 내가 바라는 미래 ⑥ 나의 내면 ⑦ 나의 시선 ⑧ 외부의 시선 ⑨ 두려움 ⑩ 최종 결과 | 십자(6장) + 오른쪽 세로 4장 — 아래 2.1 |

- 메뉴는 앞으로 하나씩 늘어납니다. 홈 화면과 배치 방식은 **메뉴가 늘어도 깨지지 않게** 설계해 주세요
- 켈틱 크로스 10장의 **모바일 배치**가 가장 까다롭습니다(전통 배치를 축소 / 세로로 재배열 / 가로 스크롤 중 제안)

### 2.1 켈틱 크로스 배치

```
            ┌───┐                 ┌───┐
            │ 5 │                 │10 │
            └───┘                 ├───┤
   ┌───┐  ┌───┐  ┌───┐            │ 9 │
   │ 3 │  │1/2│  │ 4 │            ├───┤
   └───┘  └───┘  └───┘            │ 8 │
            ┌───┐                 ├───┤
            │ 6 │                 │ 7 │
            └───┘                 └───┘
```

- 1번 위에 2번을 가로로 눕혀 겹침(장애물이 현재를 가로막는 모양)
- 이 스프레드는 **함께 읽는 카드 묶음**이 해석의 핵심입니다. 배치에서 다음이 눈에 보여야 합니다
  - 가로 흐름 3 → 1 → 4: 과거에서 미래로 가는 이야기의 뼈대(10번 결과로 이어짐)
  - 세로 흐름 6 → 1 → 5: 내면에서 바라는 미래로
  - 6번과 9번: 내면과 두려움이 짝
- 5번을 위, 6번을 아래에 두는 것과 오른쪽 세로줄의 순서는 제안입니다(참고 글에 명시되지 않음)
- 모바일에서 재배열하더라도 번호와 자리 이름을 카드마다 표시하고, 가로 흐름 3–1–4만큼은 한 줄로 유지하는 것을 권장
- 눕힌 2번 카드는 역방향 여부가 헷갈리므로 방향을 글자로 함께 표시

### 2.2 관계 스프레드 배치 (확정 — 참고 글의 그림 기준)

```
          ┌───┐
          │ 3 │               두 사람의 관계
          └───┘
     ┌───┐     ┌───┐
     │ 1 │     │ 2 │          나 · 상대
     └───┘     └───┘
   ┌───┐  ┌───┐  ┌───┐
   │ 4 │  │ 6 │  │ 5 │        내가 원하는 것 · 관계의 과제 · 상대가 원하는 것
   └───┘  └───┘  └───┘
          ┌───┐
          │ 7 │               관계의 가능성과 흐름
          └───┘
```

- 4줄 구성: 맨 위 가운데 ③ / 둘째 줄 ①·②(가운데를 비우고 좌우로) / 셋째 줄 ④·⑥·⑤ / 맨 아래 가운데 ⑦
- 둘째 줄의 ①·②는 셋째 줄의 ④·⑤보다 조금 안쪽에 놓임
- 왼쪽은 **나**(①·④), 오른쪽은 **상대**(②·⑤), 가운데 세로줄은 **관계**(③ → ⑥ → ⑦)
- 좌우 비교(①↔②, ④↔⑤)와 가운데 흐름(③→⑥→⑦)으로 읽는 스프레드이므로 이 짝이 배치에서 바로 보여야 함
- 카드를 고르는 순서는 번호 순서(① → ⑦)이고, 화면에 놓이는 위치만 위 그림을 따름
- 세로로 4줄이라 모바일에서도 폭은 3장이면 충분. 세로 길이가 길어지므로 카드 크기를 조정해 프롬프트 복사 영역이 너무 아래로 밀리지 않게
- 입력 화면 질문 예시(이 메뉴 전용): "상대가 나를 좋아하나요?" 같은 한 줄 질문보다 관계의 상태·서로 원하는 것·풀어야 할 문제를 나누어 쓰도록 유도

## 3. 화면별 요구사항

### S1. 홈
- 사이트 이름·한 줄 소개("AI와 함께 보는 타로"라는 점이 드러나게)
- 메뉴 5종 — 오늘의 운세를 가장 눈에 띄게, 각 메뉴에 장수와 한 줄 설명
- 면책 문구("재미와 성찰을 위한 콘텐츠…"), 카드 이미지 출처 링크

### S2. 상황 입력
- 고른 메뉴의 이름과 자리 미리보기
- 글 입력 칸: **선택 입력**, 최대 2,000자, 남은 글자 수 표시
- 입력 예시 문구: 질문이 구체적일수록 AI 해석이 좋아지므로 "누구와, 어떤 일로, 무엇이 궁금한지"를 쓰도록 유도. 카드 수가 많은 메뉴(켈틱 크로스)일수록 더 강조 — 문구 초안은 A가 제공
- 비워도 다음으로 갈 수 있음을 알 수 있게(예: 안내 문구 또는 "건너뛰기")
- "입력한 글은 저장되지 않으며, 복사할 프롬프트에만 포함됩니다" 안내
- 버튼: 카드 펼치기 / 메뉴 다시 고르기

### S3. 카드 선택
- 섞기 연출 → 78장 뒷면 펼침 → 메뉴의 장수만큼 선택
- 위쪽에 자리 칸(선택한 순서대로 채워짐)과 진행 표시("1 / 3 선택")
- 다 고르면 나머지 카드는 비활성, "결과 보기" 버튼 활성
- 다시 섞기 가능
- 78장을 모바일 한 화면에 펼치는 방식 제안 필요(현재: 가로로 넘기는 부채꼴)

### S4. 결과 — 가장 중요한 화면
**위: 뽑은 카드**
- 메뉴별 배치(2장)대로 카드 표시, 한 장씩 뒤집히는 연출
- 카드마다 자리 이름 · 카드 이름 · 방향. 역방향 카드는 그림을 180° 돌려 표시
- 카드를 누르면 크게 보기(선택 사항)

**아래: 프롬프트 복사**
- 한 줄 안내: "아래 프롬프트를 복사해 사용하는 AI에 붙여 넣으면 해석을 받을 수 있어요"
- **복사 버튼** — 화면에서 가장 눈에 띄는 버튼. 누르면 "복사됨" 표시(2초 정도)
- 프롬프트 미리보기: 길어서(1,100~1,700자 이상) 기본은 접힌 상태, 펼쳐 보기 가능. 복사가 막힌 브라우저를 위해 글을 직접 선택할 수 있어야 함
- 사용 방법 3단계(복사 → AI 열기 → 붙여 넣기)를 그림이나 짧은 글로
- AI 서비스 바로가기 링크: **ChatGPT**(`https://chatgpt.com`), **Gemini**(`https://gemini.google.com`) 두 곳. 복사 버튼 근처에 글자 링크로, 새 탭으로 열림. 로고 이미지는 쓰지 않음
- 버튼: 다시 뽑기 / 다른 메뉴 보기

### 공통
- 머리말(사이트 이름, 처음으로), 로딩·오류 상태(데이터를 불러오지 못했을 때)
- 뒤로 가기를 눌렀을 때의 동작(이전 화면으로) 정의

## 4. 디자인 요구사항

### 4.1 반응형
| 구간 | 폭 | 비고 |
|---|---|---|
| 모바일 | 360~767px | **먼저 설계** |
| 태블릿 | 768~1023px | |
| PC | 1024px 이상 | |

### 4.2 디자인 토큰 (`css/tokens.css`)
색(배경·글자·강조·테두리), 글꼴(제목·본문), 글자 크기 단계, 간격 단계, 모서리·그림자, 애니메이션 시간을 변수로 정의하고 화면 스타일은 변수만 참조.

- 현재 사이트는 어두운 테마/밝은 테마 두 가지 — 유지할지 하나로 갈지 제안
- 글꼴 종류와 불러오는 방식은 B가 결정. 현재 글꼴: Cinzel, Cormorant Garamond, Noto Serif KR, Noto Sans KR(Google Fonts에서 불러옴). 참고: 외부에서 불러오면 방문자의 접속 정보가 구글로 전달되고, 파일을 `assets/fonts/` 에 넣으면 외부 요청이 없음. 한글 글꼴은 용량이 크므로 종류·굵기를 최소로

### 4.3 카드 디자인
| 항목 | 요구 |
|---|---|
| 뒷면 | **자체 디자인 1종**(우선 작업). 위아래를 뒤집어도 같은 모양 — 역방향 여부가 뒷면에서 드러나지 않게 |
| 앞면 | 당분간 기존 이미지(라이더–웨이트–스미스, 퍼블릭 도메인) 사용. 자체 디자인으로 바꿀 경우 78장 |
| 비율 | 현재 이미지가 500×839~863px로 **장마다 높이가 다름** → 하나의 비율로 통일(제안: 500×860 안팎) |
| 형식·용량 | WebP 또는 JPG, 폭 500px(고해상도 화면용 1000px는 선택), 장당 100KB 이하 목표(현재 최대 약 240KB, 78장 합계 약 16MB) |
| 파일명 | `major-00`~`major-21`, `wands-01`~`14`, `cups-01`~`14`, `swords-01`~`14`, `pents-01`~`14` (01=에이스 … 11=페이지, 12=나이트, 13=퀸, 14=킹), 뒷면은 `back` |
| 위치 | `assets/decks/<덱 이름>/` — 일부만 완성돼도 됨(없는 카드는 기존 이미지로 자동 대체) |

**자체 카드 디자인 시 유의사항** (참고: `DEVELOPMENT.md` 15장의 디자인 글)

| 원칙 | 내용 |
|---|---|
| 하나의 세계관 | 78장 전체가 같은 세계관·이야기 안에 있어야 함. 장마다 화풍이 달라지지 않게 |
| 분명한 초점 | 카드마다 시선이 가는 중심이 하나. 사이트에서는 카드가 작게 보이므로 더 중요 |
| 의미 있는 요소만 | 인물·배경·동물 등 그려 넣는 것마다 뜻이 있어야 하고, 해석을 흐리는 장식은 뺌 |
| 이해되는 상징 | 사용자가 알아볼 수 있는 문화적 요소 사용, 지나치게 난해한 상징은 피함 |
| 색의 의도 | 색은 감정을 전달하는 수단 — 뜻을 정해 두고 사용. 한 장에 너무 많은 색을 쓰지 않음 |
| 스타일 일관성 | 수채화·디지털·판화풍 등 한 가지를 정해 끝까지 유지 |
| 글자 | 카드에 이름을 넣는다면 분위기에 맞는 글꼴로, 작은 화면에서도 읽히는 크기 |

**작업 방법**
- **0번 바보부터** 그려 전체 분위기의 기준으로 삼기
- 기존 덱을 여러 개 모아 분석하고, 우리 덱만의 차이점을 먼저 정하기
- 상징이 복잡한 카드일수록 A를 포함해 다른 사람의 의견 받기
- 대중성과 개성의 균형

**이 사이트에서 추가로 지킬 것**
- 프롬프트는 카드 이름만 AI에 전달하고, AI는 널리 알려진 전통 의미로 해석함 → **그림이 전통 의미와 어긋나면 사용자가 본 그림과 받은 해석이 따로 놂**. 핵심 상징은 전통을 따르고 표현 방식에서 개성을 내기
- 역방향은 그림을 180° 돌려 보여주므로, 뒤집혀도 뒤집힌 줄 알 수 있는 그림이어야 함(위아래가 비슷한 대칭 구도는 피함)
- 카드 폭 100px 안팎(모바일 목록)에서도 어떤 카드인지 구별되는지 확인

### 4.4 애니메이션
- 섞기, 펼치기, 카드 선택(자리 칸으로 이동), 뒤집기
- 기기의 "움직임 줄이기" 설정이 켜져 있으면 연출을 생략하거나 단순화(현재 구현됨 — 유지)
- 저사양 휴대폰에서도 끊기지 않게(78장 동시 움직임 주의)

### 4.5 접근성
- 본문 글자 대비 4.5:1 이상
- 누르는 영역 최소 44×44px, 겹친 카드도 잘못 눌리지 않게
- 키보드만으로 메뉴 선택 → 입력 → 카드 선택 → 복사까지 가능, 초점 표시가 보일 것
- 카드 이미지 대체 글(카드 이름·방향), 복사 완료를 화면 읽기 프로그램에도 알림

## 5. A가 제공하는 것 (엔진 사용법)

화면은 아래 함수만 사용합니다. 프롬프트 내용·카드 데이터는 A 담당이므로 화면 코드에 직접 쓰지 않습니다.

| 함수 | 언제 | 돌려주는 값 |
|---|---|---|
| `TarotEngine.load()` | 시작할 때 한 번 | 완료 신호 |
| `TarotEngine.getSpreads()` | 홈 메뉴를 그릴 때 | 메뉴 목록(이름, 장수, 설명, 자리, 배치 종류) |
| `TarotEngine.createDeck()` | 카드 펼칠 때 | 섞인 78장 `[{ cardId, orientation }]` |
| `TarotEngine.getCard(cardId)` | 카드를 그릴 때 | 이름, 이미지 경로 |
| `TarotEngine.buildPrompt(request)` | 결과 화면에서 | `{ text, length }` — `text` 를 그대로 보여주고 복사 |

`request` 형식과 예시는 `DEVELOPMENT.md` 4.1. A가 먼저 가짜 값으로 동작하는 뼈대를 제공하므로 화면 작업을 기다리지 않고 시작할 수 있습니다.

**주의**: 프롬프트와 사용자 입력 글을 화면에 넣을 때는 글자로만 넣기(`textContent`) — HTML로 넣지 않기.
