## 1. 스프레드별 배치 확정안 (PC · 모바일)

A가 작성한 시안(`docs/mockups/spread-layouts.html`)의 기본 골격을 승인하며, 스프레드별 PC·모바일 배치를 아래와 같이 확정합니다.

### 1.1 원 카드 (1장) · 오늘의 운세 (3장) · 쓰리 카드 (3장) — `layout: "row"`

```
[1. 상황]    [2. 과제]    [3. 결과]
```

* **PC · 모바일 공통**: 카드 1장 또는 3장을 가로 한 줄로 배치합니다.
* **표시 요소**: 순서대로 놓이므로 별도의 번호 배지나 카드 목록 없이 카드 위(자리 이름) / 카드 아래(카드 이름 · 정/역방향)만 간결하게 표시합니다.
* **모바일(360px) 규격**: 카드 폭 약 `84px`, 카드 간격 `0.28배`로 한 화면 폭 안에 3장이 온전히 들어가도록 유지합니다.

### 1.2 관계 스프레드 (7장) — `layout: "relationship7"`

```
          [3]             (두 사람의 관계)
       [1]   [2]          (나 · 상대)
     [4] [6] [5]          (내가 원하는 것 · 관계의 과제 · 상대가 원하는 것)
          [7]             (관계의 가능성과 흐름)
```

* **PC · 모바일 공통**: 4줄 구성(`1 · 2 · 3 · 1`)을 유지합니다. 모바일(360px)에서도 최대 가로 폭이 3장(`약 250px`)이므로 축소 없이 그대로 배치합니다.
* **시각적 연결**:
  * 좌우 비교(`① ↔ ②`, `④ ↔ ⑤`)와 가운데 관계 흐름(`③ → ⑥ → ⑦`)을 잇는 옅은 금색 점선 가이드라인을 표시합니다.
  * 각 카드 좌측 상단에 금색 원형 번호 배지(`1`~`7`)를 배치합니다.

### 1.3 켈틱 크로스 (10장) — `layout: "celtic10"`

```
[PC 배치: 십자 6장 + 우측 세로 4장]          [모바일 360px 배치: 십자 6장 + 하단 가로 4장]
          [5]            [10]                          [5]
     [3] [1/2] [4]        [9]                     [3] [1/2] [4]
          [6]             [8]                          [6]
                          [7]                   [7]  [8]  [9]  [10]
```

* **PC**: 좌측 십자(6장) + 우측 세로줄(아래 `⑦` → 위 `⑩`) 2단 구성을 유지합니다.
* **모바일(360px)**: 우측 세로 4장을 십자 아래 한 줄(`⑦ ⑧ ⑨ ⑩`)로 내립니다. 핵심 이야기 뼈대인 가로 흐름(`3 → 1 → 4`)과 세로 흐름(`6 → 1 → 5`)은 한눈에 보이도록 십자 형태를 유지합니다.
* **2번(장애물) 카드**: 1번 카드 위에 가로(90°)로 겹쳐 배치하되, 번호 배지와 방향 텍스트가 뒤집히지 않고 정방향으로 읽히도록 처리합니다.

## 2. A의 '남은 과제(1~6번)' 검토 회신 및 보완 요청

전체적인 색감, 유리 패널, 번호 배지, 흐름 점선 구성은 매우 우수합니다. `UI_DESIGN_SPREADS.md` 6장에 정리된 6가지 검토 항목에 대한 B의 결정과 디테일 보완 요청은 다음과 같습니다.

### ① 모바일 결과 화면(S4)에서 '프롬프트 복사' 영역 상단 배치 (`남은 과제 #1`)
* **이유**: 현재 관계 스프레드(7장)와 켈틱 크로스(10장) 모바일 화면에서는 `배치도 → 묶음 설명 → 카드 목록(7~10줄)`을 모두 지나야 복사 버튼이 나와 스크롤이 과도하게 길어집니다.
* **수정안**: 모바일(`767px` 이하)에서는 **스프레드 배치도 바로 아래에 '프롬프트 복사' 영역을 먼저 배치**하고, 상세 카드 목록은 그 아래로 내리거나 접기/펼치기(`카드 목록 보기 ▾`) 형태로 제공합니다.

### ② 모바일 카드 선택(S3) 78장 펼침 방식 확정 (`남은 과제 #2`)
* **결정**: 기존 시안의 한 줄 가로 부채꼴 대신 **2~3줄 격자 가로 스크롤(Grid Carousel)** 방식으로 확정합니다.
* **이유 및 규격**: 한 줄에 78장을 겹치면 모바일에서 카드 폭이 너무 좁아 손가락 오터치가 발생합니다. 카드를 2~3단 격자(줄당 26~39장)로 나누어 가로로 밀게 하면 카드별 터치 폭이 2~3배 넓어져 최소 터치 영역(`44×44px`)을 안정적으로 확보할 수 있습니다.
* **스타일 보완**: 덱 하단에 노출되는 브라우저 기본 회색 스크롤바는 CSS로 숨김 처리(`scrollbar-width: none`, `::-webkit-scrollbar { display: none }`)하고, 얇은 금빛 진행 바 또는 스와이프 안내 문구로 대체합니다.

### ③ 긴 자리 이름 줄바꿈 및 배지 겹침 해결 (`남은 과제 #3`)
* **이유**: 모바일 7장·10장 화면에서 `"관계의 가능성과 흐름"`, `"현재 상황 · 장애물"`이 두 줄로 줄바꿈되면서 아래 카드의 번호 배지(`⑥`, `⑦`)나 안내 문구와 맞닿아 보입니다.
* **수정안**: 카드 상하 간격(`row-gap`)을 여유 있게 확보하고, 좁은 그리드 칸에서는 짧은 자리명(`가능성과 흐름`, `현재 · 장애물`)을 사용할 수 있도록 데이터에 짧은 이름 필드를 추가해 주세요.

### ④ 흐름 안내선 및 겹침 카드 시인성 보완 (`남은 과제 #4` + 시안 검수)
* **흐름 점선**: 반투명 자리 칸 뒤로 점선이 비쳐 보이지 않도록 카드와 카드 사이 여백 구간에만 연결되게 다듬습니다.
* **켈틱 크로스 1·2번 겹침**: 1번 카드 정중앙에 2번 카드가 가로로 덮이면서 1번 그림이 가려지므로, 2번 카드를 중심보다 살짝 아래쪽으로 치우치게 배치하거나 결과 화면에서 카드 탭 시 확대 보기(선택 사항)를 지원합니다.
* **기타 정리**: 시안 확인용 라벨(`S2. 상황 입력` 등)은 실제 서비스 화면에서 제거하고, 홈 화면(S1)에서는 우측 상단 `"처음으로"` 버튼을 숨기며, 바닥글 출처 URL 오타(`hook252597.github.io/Tarot`)를 수정합니다.

### ⑤ 색상·글꼴 확정(`남은 과제 #5`) 및 이미지 교체(`남은 과제 #6`) 일정
* **색상·글꼴 (`R-05`, `R-11`)**: A가 시안에 잡은 색상 토큰을 기반으로 최종 확정안과 웹폰트(`.woff2`) 파일을 다음 단계에서 전달하겠습니다.
* **배경·카드 뒷면 (`R-10`, `R-08`)**: 밤하늘 배경(`assets/ui/bg-space.webp`)과 달 아이콘(`assets/ui/ic-moon.svg`) 제작이 완료되었으며, 위아래 대칭 카드 뒷면(`back`) 제작 후 일괄 전달하겠습니다.
